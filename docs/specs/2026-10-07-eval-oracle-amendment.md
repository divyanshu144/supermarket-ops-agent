# Eval oracle amendment: verify generated artifacts and stored state

## Why I am amending the approved Phase 1 work

The first independent Task 3 review found that the grader could accept a PDF with the right
header and wrong invoice contents. It also found that the bill-line oracle recomputed tax
from inputs without checking persisted tax columns. A seed reference collision could overwrite
the owner binding, and a tool-name-only grounding assertion could pass without reading the
changed product. I cannot use these checks as regression evidence until they inspect the actual
file and stored state.

## Proposed decision

I will add `pdfjs-dist` as a pinned development dependency at `6.3.289` for eval-only PDF text
extraction. I will keep it out of production imports. Mozilla's maintained Node example imports
`pdfjs-dist/legacy/build/pdf.mjs`, calls `getDocument`, and reads each page's `getTextContent()`.
The published package declares Node `>=22.13.0 || >=24`; this repo uses Node 24.13.0. I will
verify installation, TypeScript/build compatibility, and extraction against the actual invoice
generator before relying on it. I will record the exact lockfile package integrity and rerun the
full gate. Sources: [Mozilla's Node example](https://github.com/mozilla/pdf.js/blob/master/examples/node/getinfo.mjs),
[PDF.js release 6.3.289](https://github.com/mozilla/pdf.js/releases/tag/v6.3.289), and
[npm package metadata](https://registry.npmjs.org/pdfjs-dist/6.3.289).

For PPTX, I will keep parsing in Node using the existing ZIP reader and test against a real
generated deck with native charts. The grader will read actual XML entries from the artifact;
it will not accept caller-provided extracted text. If the product's current deck generator has
no native charts, I will fail the expected native-chart assertion and report that product gap
instead of synthesizing a passing file.

The bill-item table does not persist computed line totals or line tax columns. It persists
quantity, unit price, and the GST rate snapshot; the repository derives line totals and tax when
it reads a bill. I will not add a schema or business-rule change under this amendment. The oracle
will compare the persisted line inputs and persisted bill aggregate subtotal/tax/total fields
against explicit scenario values, then independently recompute each line result from the DB
inputs and compare it to the scenario's explicit line constants. The report will state plainly
that computed line fields are not persisted.

I will also close the review findings in the same Task 3 oracle slice: reject owner/sentinel ref
collisions; validate external-change references and require a fresh read of the exact changed
entity whose returned value matches the current DB snapshot; and fill the outstanding mutation
gaps for ledger/account/preferences and relevant schema and snapshot guards. Tool names remain
checked against the exported production registry.

## Scope and boundaries

The dependency is development-only and used from `src/evals/`. It does not enter production
runtime or change business rules. No PDF parsing result will be used to decide a bill total;
database rows remain the source for state assertions. I will not add a second PDF library,
change artifact generation, change GST logic, or add retrieval/observability behavior here.

## Validation

I will test a real invoice generated by the existing artifact builder, with a deliberately
wrong-file/fabricated-evidence negative case. I will inspect a real deck generated by the
existing builder and verify native chart count and expected text from its ZIP entries. I will
also use semantic mutants for the newly fixed persisted tax fields, owner/sentinel identity,
changed-entity grounding, and each added schema/state guard. I will run the focused Task 3
suite on the dedicated disposable Postgres database, then run the full verification gate.

If the pinned dependency does not work on Node 24.13.0 or the product artifacts cannot be
validated honestly, I will stop and return an updated scope proposal before substituting a
weaker assertion.
