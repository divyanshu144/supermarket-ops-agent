## Global constraints (carried forward)

- Money in integer paise, quantities in integer base units, GST in basis points.
- `store_id` and idempotency keys injected server-side via `AsyncLocalStorage`. Never tool
  parameters.
- `allowedTools` allowlist only. `Skill` permitted; `Read`/`Bash`/`Write` are not.
- MRP is tax-inclusive; tax derives from the **line total**, never per-unit × qty.
- Tools return refusals and ambiguity as **data**, never exceptions.
- Tools never return raw DB rows — `JSON.stringify` throws on BigInt, and cost price must not
  reach the model.
- Every task ends with `pnpm fmt:check && pnpm lint && pnpm typecheck && pnpm test` green
  and a commit. Never commit on `main`.

## Task 15 — Bill lifecycle repository

**Files:** `src/repositories/bills.ts`, `src/repositories/bills.test.ts`

```ts
openBill(input: { customerName?: string }): Promise<{ billId: string }>
addBillItem(input: { billId: string; productQuery: string; qty: number; unit: Unit;
                     unitPriceOverridePaise?: number }): Promise<AddItemResult>
updateBillItem(input: { billId: string; productQuery: string; qty: number; unit: Unit }): Promise<UpdateItemResult>
removeBillItem(input: { billId: string; productQuery: string }): Promise<RemoveItemResult>
getBill(billId: string): Promise<BillView>
findBills(input: { customer?: string; since?: Date; limit?: number }): Promise<BillSummary[]>
finalizeBill(input: { billId: string; paymentMode: PaymentMode; paymentRef?: string;
                      customerName?: string; allowBelowCost?: boolean }): Promise<FinalizeResult>
voidBill(billId: string): Promise<VoidResult>
```

`FinalizeResult` is a discriminated union — success, or a refusal the model must relay:

```ts
type FinalizeResult =
  | { status: 'finalized'; invoiceNumber: string; totals: BillTotals }
  | { status: 'already_finalized'; invoiceNumber: string; totals: BillTotals }
  | { status: 'insufficient_stock'; shortfalls: Array<{ name: string; wanted: string; available: string }> }
  | { status: 'below_cost'; lines: Array<{ name: string; price: string; cost: string }> }
  | { status: 'unknown_customer'; customerName: string }
```

**The finalize transaction is the heart of the task.** In one transaction:

1. `SELECT … FOR UPDATE` the bill. If already `finalized`, return `already_finalized` with the
   existing invoice — a success, not an error, and not a second decrement.
2. Lock every product row **ordered by product id**, so concurrent bills over overlapping
   products cannot deadlock by grabbing them in opposite orders.
3. Below-cost check across all lines; refuse unless `allowBelowCost`.
4. Decrement with compare-and-set:
   `UPDATE products SET quantity_base = quantity_base - $qty WHERE id = $id AND store_id = $s AND quantity_base >= $qty`.
   Zero rows → collect shortfalls, roll back, return the refusal.
5. Totals via `computeLine` per item, summed, then `roundToNearestRupee`.
6. Assign `invoice_number` from a per-store sequence.
7. Write `stock_movements` (`kind: 'sale'`, negative delta).
8. **If `paymentMode === 'khata'`**: upsert the account and write the `khata_entries` charge and
   balance update **in this same transaction**. Bill-then-charge as two transactions leaves a
   crash window where stock is gone and the customer was never billed.

`voidBill` reverses a finalized bill: restores stock, writes `reversal` movements, and reverses
any khata charge — all in one transaction. It never deletes rows.

## Task 16 — §4 invariant tests

**Files:** `src/repositories/bills.invariants.test.ts`

Each must fail if its guard is removed. Name them so a future reader knows why they exist.

- [ ] **Oversell** — bill 10 of a 6-stock item → `insufficient_stock`, stock still 6
- [ ] **Oversell at the DB** — direct negative update rejected by the CHECK constraint
- [ ] **Stock only moves on finalize** — add 4, assert unchanged; finalize, assert moved
- [ ] **Concurrency** — two bills each for 4 of a 6-stock item, `Promise.all` finalize: exactly
      one succeeds, one refuses, final stock 2, never negative
- [ ] **Idempotency** — finalize twice → same invoice, one decrement, one movement set
- [ ] **Deadlock-freedom** — two bills over the same two products added in opposite order,
      finalized concurrently, both resolve without timeout
- [ ] **Khata atomicity** — khata finalize writes charge and balance together; a forced failure
      mid-finalize leaves neither
- [ ] **Price snapshot** — add item, change product MRP, finalize → bill uses the snapshot
- [ ] **Below cost** — refuses without override, proceeds with it
- [ ] **Void restores** — void a finalized bill → stock back, reversal movements, khata reversed
- [ ] Green; commit
