# Neo4j Graph Projection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add an always-on but failure-isolated Neo4j projection, transactional Postgres outbox, read-only owner tools, backfill/reconciliation, deployment preparation, and tests.

**Architecture:** Postgres transactions append schema-derived events to `graph_outbox`; one in-process worker projects them with stable MERGE keys and only acknowledges after Neo4j confirms. Agent graph reads use a separate read-mode driver session and server-injected store id. Graph unavailability degrades health and read tools while source-of-truth writes continue.

**Tech Stack:** TypeScript, Drizzle/Postgres, official `neo4j-driver`, Neo4j Community, Docker Compose, Vitest, Zod, grammY/Claude Agent SDK MCP tool conventions.

**Spec:** `docs/neo4j-plan.md`; user requirements in the Neo4j graph feature request.

## Global Constraints

- Never connect to production Postgres, Telegram, or Railway; use disposable Docker test containers.
- No graph write may precede or participate in a Postgres money/stock commit.
- Never log credentials, event payloads, PII, transcript data, or freeform customer notes.
- Every graph query must be a constant parameterized Cypher statement and include server-derived `storeId`.
- Use READ access-mode sessions for all graph tool calls; projector alone owns graph writes.
- Neo4j failure is non-fatal to app startup, Telegram turns, Postgres writes, or the outbox.
- Commit each task after its complete verification; run `pnpm test:safe` after each task.

## Review Focus

1. A source transaction rolls back after adding outbox data: test proves neither business rows nor outbox rows persist.
2. Neo4j applies a batch but the process crashes before Postgres acknowledgement: test proves replay has no duplicate graph state.
3. A row is reclaimed after worker restart while another worker has it locked: test proves `SKIP LOCKED` and lease/claim behavior prevent premature completion.
4. A malicious product id/name or tool string attempts Cypher injection: test proves parameters are values and cannot alter query behavior.
5. A result has many rows or Neo4j stalls: test proves row limits and driver transaction timeout bound tool work.

## Plan self-review

Schema coverage: store/product/bill/item/stock/khata account/entry/pending action/audit all project; sessions are intentionally not projected because they are not business events and contain transcript provenance/PII risk. Reconciliation covers requested counts and stock sum. Failure, tenancy, injection, size and timeout guards each have a test step. Neo4j runs as one in-process worker under the existing single-replica process. No optional feature flag is introduced.
